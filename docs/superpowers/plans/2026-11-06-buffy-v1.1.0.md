# Buffy v1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Buffy 1.1.0 with a visual wardrobe, saved looks, more outfits and accessories, and interruptible idle hobbies.

**Architecture:** Extract the procedural character art into a shared classic script used by both the overlay and a new wardrobe window. Add a pure CommonJS wardrobe catalog for v2 data, migration, presets, and random looks. Add a pure classic-script hobby scheduler, wire it into the overlay's idle clock, and draw reading/coffee/stretch poses with the shared character module.

**Tech Stack:** Electron 45, Node.js 22 in CI (20+ local), Canvas 2D, `node:test`, electron-builder 26, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-06-buffy-v1.1.0-design.md`

## Global Constraints

- No new runtime or development dependencies. No bundler, UI framework, or canvas test library.
- Browser code stays classic `<script>` files because the pages load from `file://` and cannot import ES modules. Main-process and test-only modules may be CommonJS.
- Every page keeps a self-only CSP. No remote scripts, styles, fonts, or images.
- Node.js 20+ must run the source and tests; CI uses Node 22.
- Preserve existing `~/.buffy` data. A valid v1 wardrobe must migrate without losing `bow`, `hat`, `wand`, or `theme`.
- A hatched custom sprite remains a full-body replacement. Do not draw procedural outfits, accessories, or hobby props over it.
- Hobbies are cosmetic: no XP, mood, counters, daemon events, or network calls.
- The overlay window stays 300×330. The wardrobe window is 760×660 and must remain usable at 1280×720 and down to 640×560.
- Do not push a tag or publish a release until the release task and explicit user authorization.
- End each commit message with the repository's standard Codebuff footer.
- After changing files, run the task's focused test first, then `npm test` before committing. Run a visual check for every art task.
- Visual checks use an isolated `BUFFY_HOME=artifacts/v1.1-check-home` so real `~/.buffy` data is untouched. Quit any running Buffy instance before launching a screenshot run.
- The existing `--shot` path waits 2.2 seconds and exits with `--shot-exit`. Use `npx electron .` directly for deterministic foreground screenshots.

## Review Focus

1. **A v1 wardrobe loses a choice during migration.** Lavender bow, party hat, wand on, mint theme must map to exactly those v2 values. Task 2.
2. **A hand-edited or older `wardrobe.json` breaks the overlay.** Unknown items, duplicate presets, and malformed entries must fall back without a blank pet. Task 2.
3. **A hobby distracts during real work or survives an interruption.** No hobby during `working`, `needs-you`, hover, drag, or wave; an event clears it on the next frame. Task 7.
4. **Sleep cuts off a hobby or a hobby prevents sleep.** A hobby finishes, then sleep wins; idle time still ends in sleep. Task 7.
5. **The packaged app cannot load the new window or shared art.** The wardrobe page must load `character.js` before its own script, the preload API must exist, and the packaged smoke test must open the window. Tasks 1, 3, and 9.

import test from 'node:test';
import assert from 'node:assert/strict';
import { createRequire } from 'node:module';

const require = createRequire(import.meta.url);
const wardrobe = require('../overlay/wardrobe-catalog.cjs');

test('migrates a v1 wardrobe without losing a choice', () => {
  const result = wardrobe.normalizeWardrobe({ bow: 'lavender', hat: 'party', wand: true, theme: 'mint' });
  assert.equal(result.version, 2);
  assert.equal(result.outfit, 'princess');
  assert.equal(result.bow, 'lavender');
  assert.equal(result.hat, 'party');
  assert.equal(result.glasses, 'none');
  assert.equal(result.wand, 'star');
  assert.equal(result.theme, 'mint');
  assert.deepEqual(result.presets, []);

test('falls back per slot for unknown values', () => {
  const result = wardrobe.normalizeWardrobe({
    outfit: 'astronaut', bow: 'neon', hat: 'crown',
    glasses: 'x-ray', wand: 'laser', theme: 'void',
  });
  assert.deepEqual(wardrobe.lookOf(result), wardrobe.DEFAULTS);

test('saves, applies, finds, and removes a user preset', () => {
  const base = wardrobe.normalizeWardrobe({});
  const saved = wardrobe.addPreset(base, '  Date night  ', { id: 'p1', now: '2026-11-06T21:00:00.000Z' });
  assert.equal(saved.error, null);
  assert.equal(saved.preset.name, 'Date night');
  assert.equal(saved.wardrobe.presets.length, 1);
  assert.equal(wardrobe.findPreset(saved.wardrobe, 'p1').name, 'Date night');
  const applied = wardrobe.applyLook(saved.wardrobe, { ...wardrobe.lookOf(base), theme: 'sky' });
  assert.equal(applied.theme, 'sky');
  assert.equal(applied.presets.length, 1);
  assert.equal(wardrobe.removePreset(applied, 'p1').wardrobe.presets.length, 0);

test('rejects empty, long, duplicate, and over-limit preset names', () => {
  const base = wardrobe.normalizeWardrobe({});
  assert.match(wardrobe.addPreset(base, '   ', { id: 'p1' }).error, /name/i);
  assert.match(wardrobe.addPreset(base, 'x'.repeat(25), { id: 'p1' }).error, /24/);

  for (let i = 0; i < 12; i += 1) current = wardrobe.addPreset(current, `Look ${i}`, { id: `p${i}` }).wardrobe;
  assert.match(wardrobe.addPreset(current, 'One more', { id: 'p12' }).error, /12/);

Behavior:

- `normalizeWardrobe` accepts `null`, v1, and v2. `wand: true` → `'star'`; `false`/missing → `'none'`; valid `'star'` preserved. Invalid slot values use `DEFAULTS`. Presets are normalized: name trimmed to 1–24 characters, look normalized, duplicate IDs and duplicate names dropped, cap 12, malformed entries dropped. Returns `{ version: 2, ...look, presets }`.
- `lookOf` returns a fresh object with exactly the six cosmetic fields.
- `applyLook` returns `normalizeWardrobe({ ...wardrobe, ...look, presets: wardrobe.presets })`.
- `sameLook` compares the two `lookOf` objects field by field.
- `addPreset` rejects empty names, names over 24 characters, duplicate names case-insensitively, more than 12 presets, and a missing `id`. It uses `now` for `createdAt` when supplied. On error, `preset` is `null` and the wardrobe is unchanged.
- `removePreset` rejects built-in IDs when built-ins exist, rejects missing IDs, otherwise returns the filtered wardrobe.
- `findPreset` checks `CATALOG.builtinPresets` first, then user presets.
- `randomLook` picks one item per slot with `Math.min(items.length - 1, Math.floor(random() * items.length))`; valid for `random()` values 0, 0.5, and 0.999.

Create `overlay/wardrobe-preload.cjs`:

```js
const { contextBridge, ipcRenderer } = require('electron');

function subscribe(channel, callback) {
  const handler = (_event, payload) => callback(payload);
  ipcRenderer.on(channel, handler);
  return () => ipcRenderer.removeListener(channel, handler);
}

contextBridge.exposeInMainWorld('buffyWardrobe', {
  get: () => ipcRenderer.invoke('wardrobe:get'),
  update: (patch) => ipcRenderer.invoke('wardrobe:update', patch),
  random: () => ipcRenderer.invoke('wardrobe:random'),
  close: () => ipcRenderer.send('wardrobe:close'),
  onChanged: (callback) => subscribe('wardrobe:changed', callback),
});
```

- [ ] **Step 2: Implement `settings.cjs` and `hobbies.js`**

`settings.cjs` is CommonJS with `DEFAULTS` and a clamp helper. `normalizeOverlaySettings` treats a non-object as `{}`, defaults `idleHobbies` to true unless explicitly `false`, and clamps a finite `sleepAfterMs`.

`hobbies.js` is a classic script that attaches `globalThis.BuffyHobbies`. The scheduler:

- Starts with `lastActivityAt = now`, `nextAt = now + firstDelayMs`, `asleep = false`, `current = null`, `lastId = null`.
- `update(now, { hovered = false, busy = false } = {})`:
  - If `busy || hovered`: set `lastActivityAt = now`, `asleep = false`, `current = null`, `nextAt = now + firstDelayMs`, return `null`.
  - If `current` and `now >= current.endsAt`: set `lastId = current.id`, `current = null`, `nextAt = now + gapMs`.
  - If `current`: return it.
  - If `asleep`: return `null`.
  - If `now - lastActivityAt >= sleepAfterMs`: `asleep = true`, return `null`.
  - If `idleHobbies && now >= nextAt`: pick a hobby whose id is not `lastId` (uniform over the remaining choices), set `current = { id, startedAt: now, endsAt: now + durationMs }`, return it.
  - Return `null`.
- `activity(now)`: reset `lastActivityAt`, `asleep`, `current`, and `nextAt`.
- `isAsleep(now)`: return `asleep` (after the caller's most recent `update`).
- `configure(patch)`: update `idleHobbies` / `sleepAfterMs`; if hobbies become disabled, clear `current`.
